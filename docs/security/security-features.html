Layer 1

Network & Transport

  • HTTPS only — plain HTTP is redirected to an encrypted TLS connection
  • HSTS tells browsers to never connect insecurely, for a full year
  • Secure, host-locked cookies (__Host-) that a subdomain cannot plant
  • Firewall exposes only ports 443/80; the app server and MySQL listen on the host alone
  • Dedicated database account limited to the LGMED-IMMS schema
CSPnonce-based
Layer 2

Browser Protection

  • Content-Security-Policy with a fresh nonce per page blocks injected scripts (XSS)
  • CSRF tokens on every form stop forged requests from other sites
  • Clickjacking guard — pages refuse to be framed by other websites
  • HttpOnly, SameSite cookies that JavaScript cannot read
  • No-sniff, same-origin referrer & opener headers on every response
2FATOTP
Layer 3

Secure Sign-in

  • reCAPTCHA v3 turns away automated logins before the password is checked
  • Strong passwords — 12+ characters, not common, not numeric, not like the username
  • Login throttling — 5 tries per account & device, 30 per address in 15 min
  • Two-step verification by authenticator app, with one-time recovery codes and lockout on repeated wrong codes
  • 8-hour sessions that end when the browser closes
5roles
Layer 4

Access Control

  • Role-based permissions — System Administrator, Administrator, LGMED Staff, Encoder, Viewer
  • Capability checks on the server — view, encode, approve & publish are enforced in every view
  • Menu Permissions per role or per account; closed modules are refused by URL, not just hidden
  • Protected files served only after the same access check as their record
  • One account per person; no shared logins
PNPKIe-signatures
Layer 5

Data & File Security

  • Upload validation — a file's content must match its extension; disguised files are rejected
  • Sensitive-content screening flags personal data, and a human reviews before anything is published
  • e-SIRA digital signing against the DICT PNPKI chain; stored certificates are encrypted
  • Encrypted nightly backups with SHA-256 checksums; keys kept offline, apart from data
  • Data Privacy Act (RA 10173) notice acknowledged at every sign-in
Appendonly
Layer 6

Audit & Accountability

  • Tamper-resistant audit log — entries cannot be edited or deleted, even by admins
  • Sign-ins & failed attempts, with time and client address
  • Field-level change history for every create, update and delete
  • Sensitive actions — role changes, exports, access denied, 2FA on/off
  • Publication workflow — who screened, approved, published or archived
